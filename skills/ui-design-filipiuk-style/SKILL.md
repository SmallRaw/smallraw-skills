# Michael Filipiuk：把品味落实为取舍

先确定信息和视觉的主次，用有内容、有理由的细节形成产品性格，再消除干扰。完成的界面应让人知道先看什么、为什么相信它、接下来能做什么，同时留下属于这个产品的印象。

常见的视觉手感是：字体轻重克制、对齐稳定，相关内容紧凑，区块之间有呼吸；大面积表面安静，少数重点有分量；深度柔和，操作反馈利落。需要情绪的页面则让有场景感的影像、文字和材质充分表达。这些倾向用于形成连贯的观感，具体强度随产品调整。

以下判断与案例已经完成提炼，可直接用于当前设计任务。使用时只需结合当前产品的内容、品牌与界面，不需要重新查找、抓取或分析作者的推文、图片和视频。

## 先确定这次设计负责什么

从用户请求和现有界面判断范围。视觉美化（re-skin）保留功能、信息与业务流程；重设计（re-work）才涉及任务路径和信息结构的改变。发现无用功能时可以提出建议，是否实施取决于本次任务范围。

先看已有品牌、内容、组件与 tokens，以及当前做得好的地方。已有系统优先继承；新项目由 agent 提出并落实明确方向。不要要求用户先画 Figma，或为常规字号、颜色和组件选择逐项确认。

动手前用简短的设计判断说明：

- **目的与第一眼：** 用户来这里完成什么，最先应注意什么，然后看什么。
- **产品性格：** 这个产品需要传达怎样的关系或感受，把它落实到可见选择。例如“可靠”落实为稳定对齐、清楚的状态和可验证的数据；“亲近”落实为自然文案、有人的影像和柔和层次。
- **取舍：** 哪些现有特征值得保留、哪些干扰需要减弱、哪里还缺足够鲜明的表达。

小修改可在内部完成这些判断，不必另交一份长 brief。方向足够明确就继续实现；探索可以在内部做，交付时给出有理由的选择。

## 设计时用这些判断

### 让注意力有顺序

避免每个标题、数字、状态和按钮都用同等力度说话。先确定这一屏真正的视觉重心，再分配字号、字重、颜色、位置和留白。

- 数据页让重要数值和异常易于扫描，字段标签退到辅助层。页标题不必比所有业务内容都强。
- 表单让当前任务、输入与主操作构成一组；辅助解释就近出现，次要动作保持可发现但不抢主操作。
- 落地页允许标题或图像成为视觉中心，前提是它能讲清价值、建立信任或传达品牌感受。

字体默认用少量有明确职责的样式，常规与中等字重可以先建立层级。新字号或字重应解决具体的表达问题；内容需要时可以突破 starter。选择字体时看它在真实标题、数字、标签和段落中的表现。

调整后检查目光是否能自然移动。若删完元素后所有内容仍一样重，层级问题还没有解决。

例如，一个工作台把每项指标和快捷操作都做成醒目的卡片，读者会先看到容器。将相关指标组织在一个较安静的分区，降低次要操作的视觉权重，让关键数字和异常先被看到。如果任务允许改导航，再考虑把低频操作收进菜单。轻阴影与卡片仍可用于区分层次。

### 让表达有内容支撑

文案和素材本身就是设计。用产品到底做什么、用户能获得什么来组织页面，避免靠万能口号和抽象占位图填满版面。

- CTA 写具体动作，标题说明具体价值。细节来自当前产品，不能只是把示例产品的名词换掉。
- 用真实产品内容、可操作的演示，或与任务相关的照片建立可信度。示例数据应合理并明确其演示性质，不编造客户背书、使用量或评分。
- 产品截图要展示值得看的能力；照片要带来场景或感受。装饰也可以留下，但应有清楚的品牌作用。

仅仅删掉紫色渐变不会让页面拥有设计。看页面能否回答：这是谁的产品、解决什么、有什么理由值得继续看。

例如，旅行产品写“更轻松地规划旅行”，配一个抽象地球，很难让人理解它的独特价值。把内容落到同行者共同安排航班、住宿和费用，用旅行场景和可读的行程卡展示这个过程。产品能直接接收目的地并开始规划时，可以在首屏提供输入框。否则使用指向实际下一步的按钮。

### 用距离、对齐和层次表达关系

间距要让用户感知“哪些属于一起”。根据阅读和操作任务决定密度，沿用项目 spacing tokens，再校准实际观感。

- 同一任务的标签、内容与操作靠近；不同组之间留出可辨的距离。聊天按消息与回合组织，不让附件或操作行看起来属于下一条消息。
- 密集工作台保留比较与扫描效率；消费型页面给内容适当的舒展空间。不要机械地把所有间距增大。
- 用共同对齐线、重复节奏和必要的分隔组织内容。需要跨行比较时保留表格；卡片、边框与底色是否保留，取决于它们是否帮助识别关系。
- 检查容器是否重复表达了同一层关系。若留白和对齐已能分组，额外套一层卡片可能徒增重量；确实需要区分表面或交互范围时，保留相应容器。
- 图标、按钮内文字和不规则形状要看视觉重心。图标加文字按钮可调整图标侧留白和间距；独立图标按钮仍要有合适的点击区域。

先修复关系不清、对齐松散和比例失衡，再判断是否还需要额外容器或装饰。

例如，聊天内容、附件和操作各自等距分布，会让人分不清操作属于哪条消息。收紧同一消息内部的距离，把更多空白留在回合之间，就能保留气泡、附件与操作，同时让对话更连贯。

### 把颜色和效果用在值得强调的地方

让颜色有分工，避免状态、导航、装饰和主操作同时高饱和。背景、分隔和辅助文字可退后，重要内容、交互反馈和品牌表达仍需有足够力度。

- 状态色帮助识别状态；品牌色建立识别与重点。保留它们不同的职责。
- 深色界面减少刺眼的明暗跳跃和荧光色，用表面层次建立深度，同时保证正文、状态和控件可辨。
- 阴影、遮罩、圆角、照片、渐变和毛玻璃都可以有用。让它们承担层次、材质、情绪或品牌识别的工作，并保持同一界面内的逻辑一致。

如果所有页面都被改成白底、黑按钮、灰字和大留白，应重新检查产品性格是否还在。克制之后仍应有值得记住的东西。

例如，求助服务需要让人感到有人倾听。温暖、有人的照片，直接而亲近的承诺，以及容易开始的输入入口，可以共同建立这种关系。把它换成通用 SaaS 卡片会失去表达；堆满煽情影像也会妨碍求助。保留情绪，让操作清楚地嵌入其中。

### 让交互自然，让最后一点完成度可感知

动效帮助解释状态与位置变化。交互切换优先考虑自然的加减速和收尾；指示器在邻近选项间短距离移动，跨组切换可淡入淡出，避免目光被无关的长途运动牵走。具体节奏遵循产品与使用场景，尊重减少动态效果的设置。

在真实尺寸检查图标比例、光学居中、悬停、焦点、按下反馈、换行与长内容。这些细节应该支持同一种操作感，不靠额外表演证明页面被设计过。

## 修改与抛光

把模糊的不满意变成可观察的问题，再做有方向的调整：

> 标签和数值同样重，读者很难先找到金额 → 降低标签的视觉权重，保留金额与异常状态的强调 → 检查扫读时是否先看到该看的信息。

按“现象 → 影响 → 调整 → 看结果”工作。先解决影响最大的关系，比较修改前后的真实界面；不要只凭“更简洁了”判断进步。

删减时也要看保留与强化：重复文字信息的图标可以拿掉；帮助扫描的图标可以留下；缺乏可信内容的 hero 可能需要补产品演示；品牌已经鲜明的照片和色彩值得保护。简化有时意味着把多个竞争的强调合成一个更强的表达。

当下一轮只是继续变灰、变空、减少区分，而没有改善理解或操作时，停止并比较之前的版本。不要让连续的 “make it cleaner” 抹掉更好的决定。

## 在交付物上确认

用当前任务需要的页面或可点击预览验证，而不只检查设计说明。没有运行预览时明确说明；纯评审任务给出具体修改建议即可。

- 第一眼是否有明确重心，后续信息和动作是否跟得上？
- 文案、数据和图像是否具体、可信，并属于这个产品？
- 相关内容是否成组，密度是否支持实际使用，品牌性格是否仍然可见？
- 标签变长、系统字号放大、空状态、加载及主操作失败时，布局和下一步是否仍清楚？
- 交互与光学细节是否完成，最后一轮是否真的比前一轮更好？

交付时简短解释关键取舍及其效果。避免只列“改了字号、间距、圆角”；说明它们让用户更容易看懂什么、完成什么，或感受到什么。
