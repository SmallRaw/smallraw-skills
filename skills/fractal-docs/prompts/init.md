# 建立模块知识

目标是让后续修改能找到必要的原因与验证依据，不是补齐目录树。

1. 阅读现有项目入口、指令、相关实现和测试，识别真实模块边界；模块可以覆盖多个目录。排除构建产物和依赖，不按目录批量生成文档。
2. 优先复用已有 README 或设计说明。只有复杂协作、容易误改的取舍等内容缺乏说明时，才新增 `MODULE.md`；简单模块已有代码、注释和测试足够时可以不新增文档。
3. 参考 [模块示例](../starter/module.starter.md)，只写有依据且会影响修改判断的内容。需要解释原因时查相关 Git 历史、测试或测量；未查到的原因不补写成事实。
4. 从现有项目 README 或模块入口补上可点击路径。现有根 `AGENTS.md` 确有需要时，只合并一条阅读提示，保留所有用户指令；不存在时不为了文档体系专门创建指令文件。跨目录说明写明范围，各处链接到同一份正文。
5. 核对路径和关键说明，按 [check](check.md) 检查本次涉及的模块。仅改文档时无需为格式运行整个项目构建；修改代码或测试时执行相应检查。

保留现有 `CLAUDE.md`、软链接、头注释及有效旧文档，不默认重命名或删除。仅在用户要求迁移时拆出旧目录 `AGENTS.md` 中确认属于模块知识的内容，原有指令留在原处；无法区分的部分先说明疑点。

不默认创建 `FRACTAL-DOCS.md`、逐文件索引或全语言注释示例。输出实际新增/更新的文档、覆盖的模块和仍待核实的问题；无需新增时说明已有依据已足够。
