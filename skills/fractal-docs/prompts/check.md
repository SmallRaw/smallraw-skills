# 检查模块知识

参数：可选模块或文档路径。检查已有知识的准确性，不考核文档覆盖率。

1. 从项目入口和相关路径找到已有 README、MODULE、设计说明或旧分形文档；先检查请求涉及的模块，不要求每个源码目录都有文档。
2. 核对实际范围和必要主流程是否仍与实现一致，关键原因是否有历史、业务依据或测量支持。性能结论需要说明测量条件，不能把推测写成已验证事实。
3. 检查实现、测试和证据链接是否存在，关键约束是否有适当验证。实现或测试与有依据的旧要求冲突时，先报告冲突；核实要求本身已有变更依据后再改说明，不能仅凭实现现状或测试通过降低约束。无法自动判断的业务取舍明确待核实。
4. 查找重复或互相矛盾的当前结论。仍然正确但已不影响修改判断的正文也可缩短或移除；测试只表达行为时，不据此删除仍有价值的原因。跨目录模块应有一份主要说明，各入口指向它；已有用户指令保持原位。
5. 对证据充分的过期路径和错误描述直接做最小修正；业务原因不明时，先给出查到的事实和具体疑点再询问，不为每个普通文件职责逐项索取确认。

以下情况本身不算问题：没有 `FRACTAL-DOCS.md`、没有目录级 `AGENTS.md`、源码没有三行头注释、源码修改时间晚于文档、未列出每个文件、没有流程图。

不自动删除或覆盖 `AGENTS.md`、`CLAUDE.md`、软链接、旧协议或已有工作区。普通文件读取、Git 与项目测试即可完成检查；可选 CLI 只辅助导航和有限的路径提示，不能替代链接与语义核对。

输出确认的问题及依据、实际修复、相关验证和待核实项；如果没有问题，简短说明检查范围即可。不要为通过检查而补空模板或无依据的历史说明。
