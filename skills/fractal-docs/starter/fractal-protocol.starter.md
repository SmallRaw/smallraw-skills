# 模块知识维护约定（可选）

只有项目明确需要独立约定文件时才使用本示例，不默认创建 `FRACTAL-DOCS.md`。

- 共用工作规范保留在项目指令中，模块知识使用普通 README.md / MODULE.md 或现有设计文档，从项目入口按需查阅。
- 只记录必要流程、非显然的约束与取舍、原因、可以重新考虑的条件及验证依据；已有代码、注释和测试足够清楚时不重复写。
- 一个模块维护一份主要说明，可以跨目录；不要求每目录建文档、每文件补三行头注释或维护完整文件清单。
- 一次任务结束后核对相关模块的已提交与未提交变更。文档中的事实变化才修改，内部重构也可能使事实变化；历史由 Git 保存。
- 不依赖专用 CLI。保留用户的 AGENTS.md / CLAUDE.md 及有效旧文档，不自动重命名或删除。
